# Trial 67: original PHY timing comparison

The objective remains correct physical display, followed by the AOSP desktop on
the project 6.18 kernel, source-built board/vendor components and the fixed GSI.

Trial 66 did **not** repair the screen: the operator reported “没有改善” during
the native pattern and “一样花屏” after Android took over. Its 32 setup checks
passed, including the complete original 88-byte PPS in host transmission and
matching native encoder registers. F.20 was restored afterward: all 17 super
chunks, boot/DTBO, both LP slots and the full device-side super digest passed;
restored boot ID `2114bf80-253d-44c3-b015-4670eab5535b` completed Android startup.

## Evidence and hypothesis

Trial 66's native `dsi0_phy` snapshot contains the following TIMING_CTRL_0..13
values. The selected F.20 DT and official Q panel table agree with each other.

| Source | Fourteen timing bytes |
| --- | --- |
| Trial 66 registers, offsets 0xb4 through 0xe8 | `00 17 06 07 21 20 06 06 04 02 04 00 16 16` |
| Original panel table | `00 17 06 05 21 20 06 06 04 02 04 00 14 15` |

Only index 3 (`clk_trail`), 12 (`clk_pre`) and 13 (`clk_post`) differ. This is
a specific testable difference, **not an established cause** of corruption.
The comparison is to original configuration data, not a live F.20 MMIO dump.

The original panel source is pinned to
`realme-kernel-opensource/realmeX50Pro-5GPlay_AndroidQ-kernel-source`
at `24a15224fbae8ab0e8ba29a9046c06ee7a9f53a4`,
`arch/arm64/boot/dts/20607/dsi-panel-rm19795samsung-ams641rw01_1080_2340.dtsi`.
Its SHA-256 is `219f47d58006b129d9f46628389c161283debc5e04892e88ad6ff02a12074372`.
The ACK `dsi_phy_7nm.c` and `dsi_phy_7nm.xml` map these fields to the registers.
The latter is available in the pinned source mirror at
`cfa72fb3d7f89372c7e449a4de2477551ea4c29c` (git blob
`f41516dd0567ca7406b0d41c9410e28084f2b03c`). A separate downstream reference,
SM8250-Common/android_kernel_realme_sm8250 at
`b76eb6c93add8152b1aa873da0d8d7f495cccab0`,
`techpack/display/msm/dsi/dsi_phy_hw_v4_0.c`, writes lane_v4 indices directly to
those fourteen registers. That reference is **not claimed as the exact F.20
driver source**.

## Candidate and acceptance

`rmx2072-stock-phy-timing-test.patch` is default off. The explicit
`--stock-phy-test` packer option requires trial 66's stock DSC and clock flags,
and a kernel artifact carrying the matching patch digest. It adds
`msm.rmx2072_stock_phy=1` to the command line. The kernel rejects unexpected
PHY ID, C-PHY mode, SoC/panel, PHY revision, bit clock or calculated baseline.

The patch changes the timing structure before normal PHY programming. Thus
the DSI host also receives the adjusted shared pre/post values; it does not
overwrite only the PHY registers. Entry and after-program timing bytes are
logged. Entry values are not presumed to be untouched bootloader state.

Keep the 660 MHz bit clock, original PPS, single DSC route, packet layout,
source DTB/DTBO, probe, first-stage init, GSI/vendor and writable test seeds
fixed. Verify the actual PHY and host register values after native modeset,
then compare the physical native and Android phases. Successful registers,
vblank or an internal screenshot do not count as correct physical pixels.

Trial 67 has **not yet been built or tested** at this commit. A failed trial
must restore the verified F.20 environment. Staged display remains host-gated
on every boot; the current-boot guardian does not make subsequent boots
autonomous. No cold-boot or watchdog fault-injection repeat is part of this
display experiment.

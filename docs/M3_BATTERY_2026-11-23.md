# M3 battery telemetry for setup

The operator's physical touch opens the language list and scrolls normally on
trial 80. Setup then refuses continuation for low battery. BatteryService reports
present=false, level=0 and voltage=0, and `/sys/class/power_supply` is empty.
The registered source-built Health service has no kernel measurements to read.
These values do not establish that the physical battery is empty.

## Board path and bounded change

The official board 20607 tree at realme commit
`24a15224fbae8ab0e8ba29a9046c06ee7a9f53a4` identifies an external BQ28Z610
at SE16 I2C `0x888000`, address `0x55`, GPIO48/49, 100 kHz. The generic
PM8150B fuel-gauge node is not the selected board telemetry path.
The pinned ACK revision already includes the BQ28Z610 variant in bq27xxx.

Trial 81 enables the built-in bq27xxx core and I2C driver. The native SE16
binding exposes only this gauge, and the legacy SE16/wrapper2 nodes remain
disabled after the complete OEM overlay. Only GPIO48/49 are additionally
unreserved. The effective DT comparison preserves the accepted display,
touch, UFS and USB resources; changed phandle numbers resolve to the same nodes.

Nonvolatile gauge updates are disabled in the kernel configuration. The DT
does not supply programming, charger, divider, fast-charge or monitored-battery
properties. This change is for measurements; it does not qualify charging.
No capacity override or synthetic charger state is introduced.

The vendor changes label the dedicated gauge bus `sysfs_batteryinfo`, using
the existing platform Health-server read rules, and fix the touch IDC label
to `vendor_idc_file`. The candidate policy passes strict compilation with the
pinned GSI compiler and matching live policy inputs on trial 80. Neverallow
checks remain enabled. The compiled policy is not loaded into the running phone.

At this preparation stage the new gauge path has **not run on the handset**.
Next acceptance is a real gauge response, plausible power_supply measurements,
matching Android battery state under enforcing, and continuation of setup by
physical touch. Preserve the same GSI and writable RAM test seeds. The accepted
display parameters stay fixed. USB loss across screen off/on remains a separate
unresolved issue; no speculative USB patch is included here.

During the diagnostic session, the temporary RAM-backed screen timeout is set
to 30 minutes and recorded. Powered stay-awake alone is insufficient when the
new gauge reports a present, discharging pack while charger integration is
unported. This avoids automatic screen sleep disrupting the known USB path
during measurement; it does not override the reported battery state.

The read-only acceptance collector was exercised against the unchanged trial-80
phone. All three samples reject the missing gauge and report level 0, with no
Android battery override. This is an expected negative control, not a device
pass. [Control record](../build/device/m3-battery80-negative-control-2026-11-23.json)

Voltage comparison must account for source semantics: the upstream gauge reads
pack voltage from register 0x08, while the OEM driver returns the maximum of its
two cell voltages after a manufacturer-access query. The new path keeps the
upstream pack measurement and unit conversion; it does not divide values to
imitate an OEM result. Capacity register 0x2c and temperature register 0x06 match
the OEM path. Upstream current uses average-current register 0x14, whereas the
OEM BQ28Z610 branch selects instantaneous-current register 0x0c. Real charging
control, calibration and cell-balancing acceptance remain outside this trial.

## Later setup observation while the battery build runs

Trial 80 later focuses Google SetupWizard NetworkActivity. Its process repeatedly
crashes with a NullPointerException calling WifiManager.isVerboseLoggingEnabled()
on a null object. The wifi Binder service and android.hardware.wifi feature are
absent. system_server and SurfaceFlinger keep their original PIDs and the boot
ID is unchanged; the screenshot shows status icons over a black application
area. Battery telemetry remains the isolated trial-81 change. The network-page
service prerequisite is the next setup blocker; no functional Wi-Fi result is

# M3 battery telemetry for setup

The operator's physical touch opens the language list and scrolls normally on
trial 80. Setup then refuses continuation for low battery. BatteryService reports
present=false, level=0 and voltage=0, and `/sys/class/power_supply` is empty.
The registered source-built Health service has no kernel measurements to read.
These values do not establish that the physical battery is empty.

## Board path and bounded change

The official board 20607 tree at realme commit
`24a15224fbae8ab0e8ba29a9046c06ee7a9f53a4` identifies an external BQ28Z610
at SE16 I2C `0x888000`, address `0x55`, GPIO48/49, 100 kHz. The generic
PM8150B fuel-gauge node is not the selected board telemetry path.
The pinned ACK revision already includes the BQ28Z610 variant in bq27xxx.

Trial 81 enables the built-in bq27xxx core and I2C driver. The native SE16
binding exposes only this gauge, and the legacy SE16/wrapper2 nodes remain
disabled after the complete OEM overlay. Only GPIO48/49 are additionally
unreserved. The effective DT comparison preserves the accepted display,
touch, UFS and USB resources; changed phandle numbers resolve to the same nodes.

Nonvolatile gauge updates are disabled in the kernel configuration. The DT
does not supply programming, charger, divider, fast-charge or monitored-battery
properties. This change is for measurements; it does not qualify charging.
No capacity override or synthetic charger state is introduced.

The vendor changes label the dedicated gauge bus `sysfs_batteryinfo`, using
the existing platform Health-server read rules, and fix the touch IDC label
to `vendor_idc_file`. The candidate policy passes strict compilation with the
pinned GSI compiler and matching live policy inputs on trial 80. Neverallow
checks remain enabled. The compiled policy is not loaded into the running phone.

matching Android battery state under enforcing, and continuation of setup by
physical touch. Preserve the same GSI and writable RAM test seeds. The accepted

During the diagnostic session, the temporary RAM-backed screen timeout is set
to 30 minutes and recorded. Powered stay-awake alone is insufficient when the
new gauge reports a present, discharging pack while charger integration is
unported. This avoids automatic screen sleep disrupting the known USB path
during measurement; it does not override the reported battery state.

The read-only acceptance collector was exercised against the unchanged trial-80
phone. All three samples reject the missing gauge and report level 0, with no
Android battery override. This is an expected negative control, not a device
pass. [Control record](../build/device/m3-battery80-negative-control-2026-11-23.json)

Voltage comparison must account for source semantics: the upstream gauge reads
pack voltage from register 0x08, while the OEM driver returns the maximum of its
two cell voltages after a manufacturer-access query. The new path keeps the
upstream pack measurement and unit conversion; it does not divide values to
imitate an OEM result. Capacity register 0x2c and temperature register 0x06 match
the OEM path. Upstream current uses average-current register 0x14, whereas the
OEM BQ28Z610 branch selects instantaneous-current register 0x0c. Real charging
control, calibration and cell-balancing acceptance remain outside this trial.

## Trial 81 handset result

The native SE16 controller and gauge at 2-0055 probe successfully at 28.67 s.
Boot 5c2c807b-ff25-41bb-94bb-44eb3cb4b2a9 reaches enforcing Android 17 with
system_server 2425 and SurfaceFlinger 2171. Three samples show a present pack,
capacity 100%, pack voltage 8.651 V, and temperature about 35.4-36.0 C. Android
BatteryService reports present=true, level=100 and voltage=8651 mV; its temperature
agrees within the sampled update interval. No override is installed. The gauge
attributes carry sysfs_batteryinfo and Health reads them under enforcing.

InputReader now loads the project Goodix IDC file. The same-boot ADB retention
check passes and the phone remains in GSI. The current staged-display profile
still needs the host observer after a reboot; unattended restart is not qualified.
Charging detection/control is not yet integrated: USB/AC powered remain false.

The operator selects language and Next and reports a black page. The same boot
records repeated SetupWizard NetworkActivity NullPointerExceptions on
WifiManager.isVerboseLoggingEnabled(). This is a separate framework-service
blocker; battery telemetry acceptance does not establish Launcher acceptance.

## Next candidate: setup network service

The pinned SystemServer source starts WifiService and WifiScanningService only
when android.hardware.wifi is declared. The GSI Wi-Fi APEX and service JAR are
already mounted, but the minimal project vendor did not declare the board's
Wi-Fi feature. Trial 82 adds one permissions XML under the existing
vendor_configs_file label. Its inventory comparison adds exactly that file,
changes no existing vendor file, and preserves the split policy. It retains
the trial-81 kernel, trees, battery/input/display paths and test seeds.

The intended acceptance is a registered wifi framework service and a rendered
setup network page without the null-WifiManager crash. This does not implement
the Wi-Fi kernel driver, radio firmware transport or HAL and is not evidence of
scanning or a working connection. Offline setup remains the desktop path.
[Source scope check](../build/device/m3-setup82-scope-2026-11-23.json)

## Trial 82 framework prerequisite result

Boot 09d2dd9a-bf2a-438f-bc6e-03e3f5665843 reaches API 37, enforcing and
sys.boot_completed=1. The Wi-Fi feature is now visible; both wifi and wifiscanner
Binder services register. The log records StartWifi and StartWifiScanning.
The welcome page renders with system_server 2415, SurfaceFlinger 2141 and
audioserver 2137, and the crash buffer is empty before the Next retest. InputReader
loads the project Goodix IDC. BatteryService still reports present=true,
level=100 and pack voltage=8651 mV without an override.

The 196.25-second same-boot ADB check passes and GSI is retained. The original
recovery set is reused; this run verifies the previous and new candidate
container, without another stock backup read or a write to stock userdata.

The operator subsequently confirms the WLAN page and offline continuation to
date/time and protection screens. The network-page black-screen regression is
resolved. Skipping protection then returns to date/time because the installed
GSI Settings callback does not set its skip result. A separate Launcher start
exposes the missing AppWidgetService. See the [setup follow-up](M3_SETUP_2026-11-23.md).
No radio/connection result is claimed. USB recovery across screen sleep and the
host requirement after reboot remain open.

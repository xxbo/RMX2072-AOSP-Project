endpoint enumeration, exact firmware/calibration selection, real scanning,
association/DHCP and WLAN traffic.

The optional `--wifi` source DT now adds the ACK PCIe0/GEN3x1 resources and
QCA6390 PMU sequence. It retains board 20607's PM8009 S2 (`smpf2`) digital
rail, PM8150 S6 AON, S4 IO, S5 1.9 V and PM8150L S8 1.35 V RF rails.
Only GPIO20/21/79/80/81 are added to the accepted TLMM mask. The original
CNSS/PCIe nodes remain parked after the complete OEM overlay. A source build
passed the existing USB/UFS/PON/display/input/gauge/performance checks and the
new PCIe/PMU check. Deliberately substituting S6 for the PM8009 digital supply

but `Phy link never came up`. The earlier first failure is
`m3_wlan_digital: failed to get the current voltage: -ENOTRECOVERABLE`,

Pinned ACK uses 320 + 16*n mV for ordinary PM8009 S2: neither 950 nor 952 mV
is representable. Its regulator core tries to initialize, ignores that setter
return, rereads the still-unknown cached selector and reports -131. The OEM
driver instead sends `ceil(min_uV/1000)` directly to RPMh, so its 950..952 mV
consumer vote cannot be copied as an ACK selector constraint.

Upstream [PM8009-1 correction](https://kernel.googlesource.com/pub/scm/linux/kernel/git/stable/stable-queue/+/refs/tags/v6.12.41/releases/5.10.20/regulator-qcom-rpmh-regulator-add-pm8009-1-chip-revi.patch)
identifies the special SM8250 revision and its 900 + 16*n mV table. Trial 92
uses that compatible and the upstream RB5 900..952 mV constraint, retaining
board 20607's `smpf2` connection. This is a source-backed board inference, not
a fresh PMIC revision-register measurement. The driver's initial vote is
900 mV; this range stays within the OEM provider's 512..1100 mV limits and
does not raise the previous consumer ceiling. Successful registration and
endpoint discovery still require the next physical result. Offline validation
now also checks that every WLAN rail range contains an ACK voltage selector.

The next firmware inputs are [inventoried separately](../build/device/m3-wifi-firmware-source-2026-11-25.json):
linux-firmware commit `599764611a8ac213c6aa6dad17c941c2f46b53cb`, QCA6390 hw2.0
AMSS/M3 program images, notice and license, verified against Git blob identities

## Audio and vibration: no physical acceptance

AudioService is present, but the project audio HAL still has no PCM-backed
ports/routes. A shell read of /proc/asound/cards is denied and is not evidence
that the file or hardware is absent. Prior F.20 evidence identifies TFA98xx
amplifiers at I2C 4-0034/0035; ADSP/Q6 and ASoC/codec routing remain prerequisites.
The selected 20607 `kona-audio-overlay.dtsi` also describes WCD938x RX/TX over
SoundWire, not a generic speaker-only codec. `kona-audio.dtsi` ties TFA reset
GPIO91/130 to 0x35/0x34 and requests `tfa98xx_19795.cnt`. Speaker firmware and
calibration must therefore follow this board's amplifier path.
VibratorManager currently reports an empty vibratorIds list. F.20 identifies
AW8697 at a8c000.i2c/0x5a; board source gives reset GPIO72 and IRQ47. This needs
an independent native driver/HAL and short-pulse/stop acceptance.

## Setup: confirmed cancellation-code defect

Both provisioning flags remain zero. Installed Settings SHA256 is
`4c184e7abd0f4f38b09f2d2434eec778003f970bca35d2a17bba673fa7015b37`;
SetupWizard SHA256 is
`bcb27bb456451911e1760c187c477c57a6431e72e36e3a0210222ba50b318064`.
The positive skip callback calls uploadMetrics(11,true) then finish(), but
neither it nor the metrics helper sets Activity result. Inspection of the
actual SetupWizard LockScreenWrapper confirms request 10002 treats result 0 as
cancellation and maps 11 to skip. Its launch explicitly restricts the intent
to com.android.settings, so registering an unrelated implicit-intent shim
would not fix this installed flow. A resource-only Settings overlay cannot
add the missing code. Preserve credential choices and do not mark provisioning
complete artificially. A compatible source fix/deployment route remains open.

Settings certificate SHA256 is
`4b92abd4c1bba163b3e2ac76669942b51a2bbdb5d7ab7914e4e341b14be8b827`,

`c8a2e9bccf597c2fb6dc66bee293fc13f2fc47ec77bc6b2b0d52c11f51192ab8`.

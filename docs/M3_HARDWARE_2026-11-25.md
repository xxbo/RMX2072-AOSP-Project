## Wi-Fi: native kernel prerequisites in progress

Current GSI has no wireless netdev, no ieee80211 class and no enumerated PCI
endpoint in the shell-readable PCI device directory. WifiService exists but is
disabled. The previously measured F.20 PCI endpoint is 17cb:1101 (QCA6390).
The optional source build now includes the pinned ath11k PCI, MHI/QRTR/QMI,
Qualcomm PCIe/QMP PHY and QCA6390 power sequencing prerequisites. Compiling the
stack alone is not radio acceptance. Do not load the F.20 4.19 wlan module.

Board supplies/GPIOs must come from RMX2072 board 20607 and its selected source
layout, not copied from another device. The same-chip
[Linux 6.18 elish description](https://github.com/torvalds/linux/blob/v6.18/arch/arm64/boot/dts/qcom/sm8250-xiaomi-elish-common.dtsi)
is a binding reference for QCA6390 power sequencing only; its calibration
variant must never be used as RMX2072 calibration. Next gates are controller/
endpoint enumeration, exact firmware/calibration selection, real scanning,
association/DHCP and WLAN traffic.

The optional `--wifi` source DT now adds the ACK PCIe0/GEN3x1 resources and
QCA6390 PMU sequence. It retains board 20607's PM8009 S2 (`smpf2`) digital
rail, PM8150 S6 AON, S4 IO, S5 1.9 V and PM8150L S8 1.35 V RF rails.
Only GPIO20/21/79/80/81 are added to the accepted TLMM mask. The original
CNSS/PCIe nodes remain parked after the complete OEM overlay. A source build
passed the existing USB/UFS/PON/display/input/gauge/performance checks and the
new PCIe/PMU check. Deliberately substituting S6 for the PM8009 digital supply
was rejected. These are offline checks, not handset enumeration.

Kernel run 45614307968 failed at the configuration gate: GKI's RFKILL=m
bounded CFG80211 and its dependents to modules. Commit 3099624 makes RFKILL
built-in. Replacement run 45616137172 reached module packaging, then rejected
the stale GKI output declarations for `libarc4.ko`, `pwrseq-core.ko` and
`rfkill.ko`: those objects are now built-in. The WLAN build now removes exactly
those three declarations from its staged copy and retains Kleaf's strict check
for all remaining modules. Non-WLAN builds keep the original list. No
failed-build image was installed.

The installed Wi-Fi APEX contains `wpa_supplicant_mainline` and its init rc;
the framework resource enabling it is currently false. AOSP Wi-Fi revision
`67beff9acf0e91046d2a9a36a68cb06ef263d1f1` supports mainline supplicant with
Android 17 policy, the feature flag and the resource enabled. WifiNative also
has an explicit station-interface path without a vendor Wi-Fi HAL. These are
candidate integration paths after native WLAN discovery, not demonstrated
connection results. The live wificond binder service is `wifinl80211`.

The optional project Wi-Fi RRO is now source-built and signature-verified
against the exact GSI resource APK. Its target is the actually installed
`com.google.android.wifi.resources`, with `WifiCustomization` explicitly
allowing vendor overlays for `config_wifiMainlineSupplicantEnabled`. The
[build record](../build/device/m3-wifi-overlay-2026-11-25.json) remains
`installed=false`: trial 91 keeps vendor unchanged for PCIe isolation. The
Android 17 policy, mainline feature flag and successful service start still
need on-device acceptance after a real WLAN netdev is available.

## Audio and vibration: no physical acceptance

AudioService is present, but the project audio HAL still has no PCM-backed
ports/routes. A shell read of /proc/asound/cards is denied and is not evidence
that the file or hardware is absent. Prior F.20 evidence identifies TFA98xx
amplifiers at I2C 4-0034/0035; ADSP/Q6 and ASoC/codec routing remain prerequisites.
The selected 20607 `kona-audio-overlay.dtsi` also describes WCD938x RX/TX over
SoundWire, not a generic speaker-only codec. `kona-audio.dtsi` ties TFA reset
GPIO91/130 to 0x35/0x34 and requests `tfa98xx_19795.cnt`. Speaker firmware and
calibration must therefore follow this board's amplifier path.
VibratorManager currently reports an empty vibratorIds list. F.20 identifies
AW8697 at a8c000.i2c/0x5a; board source gives reset GPIO72 and IRQ47. This needs
an independent native driver/HAL and short-pulse/stop acceptance.

## Fingerprint: source path audit, not an enrolled sensor

No fingerprint service is registered and biometric Sensors is empty. The OEM
board 20607 source describes Goodix optical G3, IRQ23/reset68 and two supply
rails. This source description is not a fresh physical chip-ID read. The secure
sensor protocol, TEE trustlet, Gatekeeper/authentication tokens and display
illumination integration need separate evidence before enrollment can be
advertised. Do not implement a successful fake enrollment/authentication HAL.
The OEM Goodix optical TEE driver exposes power/reset/IRQ, event and clock
control IOCTLs; porting that control device alone would not provide biometric
matching or valid authentication tokens.

## Setup: confirmed cancellation-code defect

Both provisioning flags remain zero. Installed Settings SHA256 is
`4c184e7abd0f4f38b09f2d2434eec778003f970bca35d2a17bba673fa7015b37`;
SetupWizard SHA256 is
`bcb27bb456451911e1760c187c477c57a6431e72e36e3a0210222ba50b318064`.
The positive skip callback calls uploadMetrics(11,true) then finish(), but
neither it nor the metrics helper sets Activity result. Inspection of the
actual SetupWizard LockScreenWrapper confirms request 10002 treats result 0 as
cancellation and maps 11 to skip. Its launch explicitly restricts the intent
to com.android.settings, so registering an unrelated implicit-intent shim
would not fix this installed flow. A resource-only Settings overlay cannot
add the missing code. Preserve credential choices and do not mark provisioning
complete artificially. A compatible source fix/deployment route remains open.

The GSI identifies as CP3A.260905.010/16176746, user/release-keys. The installed
Settings certificate SHA256 is
`4b92abd4c1bba163b3e2ac76669942b51a2bbdb5d7ab7914e4e341b14be8b827`,
whereas the public AOSP platform test certificate is
`c8a2e9bccf597c2fb6dc66bee293fc13f2fc47ec77bc6b2b0d52c11f51192ab8`.
They do not match: an engineering-key APK cannot replace this shared-UID system
Settings package. The inspected AOSP Android 17 release `SetupSkipDialog`
sets RESULT_SKIP before finish; this installed GSI's listener-based callback
omits it. No flag branch precedes that callback in the installed method.
The fix belongs at that callback's result boundary; weakening signature checks
or synthesizing provisioning completion is not a fix.

The audit's lshal tool itself crashed with a null dereference; those crash-buffer
entries belong to lshal, not the inspected audio/biometric services. Further
inspection uses framework service dumps and VINTF declarations instead.

## Existing stock recovery inventory, without another image copy

`inventory_stock_vendor.py` maps the original recovery chunks through the LP
extents and reads EROFS directory metadata in place. It verifies the locally
consumed chunks against acquisition digests; it has no handset I/O. No second
stock image or full extraction was created. The selected
[inventory](../build/device/m3-stock-hardware-inventory-2026-11-25.json) records:

- ODM `/etc/wifi/bdwlan.elf`, 57,908 bytes; applicability to ath11k still needs
  board-ID/format verification, not merely a filename substitution.
- ODM AW8697 base/170/235/235_19161 waveforms. Board 20607's OEM device_id=832
  selects the 0832 motor parameters; do not use the default 0815 parameters.
- ODM `tfa98xx.cnt`, 3,877 bytes, whose name differs from the old Android Q DT's
  `tfa98xx_19795.cnt`. The current F.20 amplifier configuration must be checked
  before playback, rather than assuming that old filename is authoritative.
- ODM Goodix G3 implementations and `goodixfp.mdt`/segments. The original
  manifest registers Android fingerprint HIDL 2.3 plus Oplus 2.1. Its rc starts
  `fps_hal` at late_start, uses `/dev/goodix_fp`, and controls optical illumination
  through `/sys/kernel/oplus_display/hbm`. The init configuration is evidence of
  dependencies, not a reason to copy its broad device-node permissions.

## Selected hardware files and format checks

`extract_stock_hardware.py` verified the existing local chunks, temporarily
materialized only logical ODM for the checked host EROFS decoder, and deleted
that temporary image in `finally`. Only four selected small files remain in
the private workspace; no additional recovery image is retained or handset
partition read. The uncompressed amplifier file also matched the independent
flat-file reader. Public [metadata](../build/device/m3-stock-hardware-files-2026-11-25.json)
contains sizes/hashes, not the proprietary files.

The 57,908-byte board file is an ELF32 ARM wrapper around a 56,180-byte board
payload. Pinned ACK `ath11k/qmi.c` explicitly detects ELF and sends
`BDF_TYPE_ELF`; `core.c` retains the `board.bin` API-1 fallback. Preserve the
original wrapper. This establishes a candidate format path, not QMI board-ID
or firmware acceptance. The TFA container identifies `9874`/`tfa9874` and
receiver/speaker/calibration profiles; this is file evidence, not a chip-ID
measurement. AW8697's selected 235 Hz waveform has a valid OEM header checksum
(26183) and RAM base 0x800; no waveform was uploaded or actuator driven.
